# 任务目标与验收标准冻结

## 任务背景
用户在 MuseFlow (26Flow) 中反馈：
1. 插件生成时会启动所有生成功能，导致单独修改某个功能/场景时，全部内容都被迫重新生成一遍。
2. 希望将插件中的“生图模型”改为可选项（下拉列表），并能够设置/自定义自己的生图模型。
3. 视频生成失败时，整个工作流会直接卡住，无法继续进行。

## 验收标准 (Acceptance Criteria)
- **AC-001: 单节点生成与依赖缓存保护**
  - 在节点自身的“▶ 生成图片/视频”按钮或右键上下文菜单执行单节点生成时，只强制重新生成被点击的目标节点。
  - 对于该目标节点所依赖的上游节点（如作为参考图来源的上一张图片，或作为尾帧连续性来源的上一个视频片段），若已存在有效资产（asset.url），必须直接复用，绝不清空其 asset 或重新发起请求。
  - 只有当上游依赖项从未生成（缺少 asset.url）时，才按需前置生成该依赖项。

- **AC-002: 智能增量运行与全量重跑控制**
  - 顶栏“▶ 运行”按钮默认支持智能增量模式，自动跳过已经生成成功且未做修改的节点，状态栏提示跳过已完成项，避免改动单个节点引发全库重跑。
  - 提供显式的“↺ 重新生成全部”入口（如顶栏下拉/右键操作/设置选项），方便用户在需要时一键全量重跑。
  - 画布右键菜单增加“▶ 运行选中节点”，支持选中 1 个或多个节点时仅运行选中节点。

- **AC-003: 生图模型可选项化与自定义模型配置**
  - 将“生成图片”节点的生图模型输入框改造为下拉选择器（`<select>`），内置常用预设模型选项（如 `muse-image`（Muse 默认）、`flux-1-schnell`、`flux-1-dev`、`dall-e-3`、`sd-xl` 等）以及“+ 自定义模型...”。
  - 支持用户直接输入并保存自己的自定义模型名称，自动追加到选项中，并持久化到扩展配置。
  - 在“设置”弹窗中增加“生图模型配置”专区，允许用户设置默认生图模型、管理自定义模型列表。
  - 发送生成请求时，将用户选择的模型标识完整透传并在提示词中增加规范的模型指令指示。

- **AC-004: 确定性门禁与测试验证**
  - `app.js`、`muse-bridge.js` 通过 Node.js 语法校验（`node -c`）。
  - 编写并运行自动化逻辑测试，对节点运行调度过滤算法、模型选择及持久化逻辑进行全量自动化回归验证，客观输出 exit code 0。

- **AC-005: 视频生成快速失败检测与熔断（Fast-Fail）**
  - 在 `muse-bridge.js` 中增加页面报错检测与生成停止检测机制，一旦 Muse 页面提示生成错误、额度不足或停止按钮消失超过 2.5 秒但未产生有效媒体，立即中断并返回具体错误原因，杜绝在 600 秒循环中死等卡死。

- **AC-006: 工作流多节点容错推进与故障隔离（Fault-Tolerance）**
  - 在 `app.js` 工作流调度器中，单视频节点生成失败时，自动标红记录错误并隔离异常，工作流继续执行后续无依赖的独立视频/图片节点。
  - 下游若依赖上一片段的连续性（Continuity）尾帧，前置失败时下游安全跳过并提示等待前置，不中断其它独立分镜。
  - 执行完毕后保证 `state.isRunning` 为 false、按钮恢复为 `▶ 运行`，状态栏清晰汇总成功与失败数量，支持单独针对失败项增量重试。
